# 総研 顧客管理アプリ（GAS初期版）

Sansan形式のCSV、入力画面、スマホで撮影した名刺画像から顧客を登録する、独立型Google Apps Scriptアプリです。保存先はGoogleスプレッドシート、CSVと画像の原本保管先はGoogle Driveです。

## できること

- 顧客の検索、状態による絞り込み、登録、編集
- 見本のSansan 60列CSVの取込、原ファイル・全列値の保持、空行と件数の記録
- 既存顧客とCSV内の両方に対する重複候補の表示、人による関連付け・別人登録
- 名刺の撮影・写真選択、Google Driveの文字読取、メール・電話の入力候補、確認してから登録
- 取得経路、購読同意、停止状態の別管理、編集・再取込でも停止を保持
- 変更前後と操作したアカウントの履歴、更新競合の検知、途中失敗後の復旧

メール送信、配信停止の外部公開ページ、停止解除、公開購読フォームは含みません。購読同意の確認方法と停止範囲の業務ルールはレビュー待ちです。ここで表示する「同意記録あり」は、本番配信の許可ではありません。

## 最初に用意するもの

1. 運用予定のGoogleアカウントのDriveに「総研_顧客管理」フォルダを作成。
2. 空のGoogleスプレッドシート「総研_顧客データ」を作成。列やシートを手作業で準備する必要はありません。
3. 独立型Apps Scriptプロジェクト「総研_顧客管理アプリ」を作成。
4. 同じ管理フォルダに「原本保管」フォルダを作成。CSV原本、名刺原画像、文字読取用Googleドキュメントが入ります。

最初は共有を自分だけにします。公開リポジトリに顧客CSV、名刺画像、実際の顧客情報、Google連携IDを保存しないでください。

## GASへの配置

`gas/`内の次の4ファイルが配置用です。生成済みなので、Node.jsを使わず配置できます。

| GitHubのファイル | Apps Scriptエディタで作るファイル |
|---|---|
| `gas/Code.gs` | スクリプト `Code`（初期の内容を置き換える） |
| `gas/Core.gs` | スクリプト `Core` |
| `gas/Index.html` | HTML `Index` |
| `gas/appsscript.json` | プロジェクト設定で「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にして内容を配置 |

`src/`は開発用の元ファイル、`gas/Index.html`と`gas/Core.gs`は生成物です。生成物だけを直すと、次回生成で変更が消えるため、ソース修正は`src/`で行います。

### 接続設定

GASの「プロジェクトの設定」→「スクリプト プロパティ」に次を追加します。実際の値はGitHubへコミットしません。

| プロパティ名 | 値 |
|---|---|
| `SPREADSHEET_ID` | スプレッドシートURLの`/d/`と`/edit`の間にあるID |
| `ARCHIVE_FOLDER_ID` | 原本保管フォルダURLの`/folders/`の後のID |
| `ALLOWED_USERS` | 利用を許可するGoogleアカウントのメール。複数なら半角カンマ区切り |

別名メールとGoogleアカウントのメールが異なる場合は、エディタで`showMyAccount`を実行し、実行ログに表示されるアカウントを`ALLOWED_USERS`へ設定します。業務用の送信メールアドレスを推測して入れません。

### 画像の文字読取

マニフェストにDrive API v3を宣言しています。GASの「サービス」に「Drive API v3」が表示されることを確認します。標準Google Cloudプロジェクトを使う場合は、そのプロジェクト側のDrive API有効化も必要です。管理者がDriveやApps Scriptの利用を制限している場合は確認を受けます。

画像をGoogleドキュメントへ変換し、その文字を読み取ります。外部の生成AI APIキーは使いません。読取結果から氏名・会社名や同意を自動確定せず、人が確認して入力します。読取に失敗しても画像の保存記録を返すため、手入力で続けられます。設定を直して同じ画像を読み直すと、画像原本を二重保存せず再試行します。

参考：[高度なDriveサービス](https://developers.google.com/apps-script/advanced/drive)、[画像を含むファイルの変換](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。

### 初期化と自分だけのテスト公開

既に本人限定のWebアプリURLを受け取っている場合は、URLを普段ログインしているブラウザへコピーして開きます。初回承認後、未初期化なら「管理シートを作成して始める」を押します。GASエディタでの操作を省けます。以下は新規に配置する場合の手順です。

1. エディタから`setupApp`を実行し、必要なGoogle権限を確認・承認します。スプレッドシート・Drive・Googleドキュメント・アカウントのメール取得を利用します。Gmail権限は要求しません。
2. スプレッドシートに管理用シートが作成されたことを確認します。
3. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選びます。
4. 実行者は「ウェブアプリケーションにアクセスしているユーザー」、アクセスできるユーザーは最初は「自分のみ」にします。実際の選択肢が組織の設定で異なる場合は管理者へ確認します。
5. 表示されたURLを開き、架空の顧客を1件登録・編集します。
6. スプレッドシートの顧客一覧と変更履歴、Driveの原本、再読込後の状態を確認します。

複数人へ広げる際は、アプリへのアクセスに加え、スプレッドシートと原本保管先の必要な権限、`ALLOWED_USERS`もそろえます。アカウントのメールが取得できない場合はアクセスを拒否します。「全員に公開」して利用する構成ではありません。送信ドメイン・Gmailの方式はこのアプリに依存させていません。

参考：[GASウェブアプリの実行者と公開](https://developers.google.com/apps-script/guides/web)、[アカウント情報の取得制限](https://developers.google.com/apps-script/reference/base/session)。

## スプレッドシートとの連動

アプリの登録・編集のたびにスプレッドシートへ保存し、画面の「最新の情報に更新」で読み直します。顧客一覧、重複確認、取込履歴、CSV原行、変更履歴、名刺画像、停止台帳、処理の復旧記録を作ります。

初期版は**アプリ画面で編集し、スプレッドシートは閲覧・点検用**とします。管理用JSON列が保存の正本なので、表の表示列だけを直接直してもアプリへ反映されません。JSON列や復旧記録の直接編集・行削除は行わないでください。シートの直接編集も連動させる機能は未実装です。

保存時は同時実行を制限し、変更計画を先に記録してから管理表へ反映します。途中で失敗した場合、次の操作で未反映の計画を再反映します。原本だけ保存された後に処理が失敗すると、顧客に未関連付けのファイルがDriveへ残る場合があります。原本を自動削除せず、処理記録と照合します。

## 初期版の制限と試験

- Sansan CSVはこのプロジェクトで確認した60列の順番に限定。異なる形式は取込を停止します。
- CSVは2MB・内容あり200件/回、画像はJPEG/PNG・5MB/回、顧客は2,000件まで。GAS実行時間内に収まる実件数はGoogle上で測定が必要です。
- CSVのEmail(2)も保存しますが、複数宛先の配信先選択は未実装です。該当顧客は確認待ち表示です。
- 同一人物への関連付けは取得元情報を履歴へ残し、既存プロフィールを維持します。氏名・会社・メールを更新したい場合は顧客編集画面で判断して修正します。
- 共有メール、候補未判断は確認待ち。停止解除と既存顧客同士の統合・誤統合の分割は未実装です。
- 保存量は取込・変更履歴とともに増えます。復旧記録には顧客データの写しを含むため、同じ閲覧制限・保存期間の対象にします。大量運用前には容量・実行時間・履歴の保管方針を見直します。
- 保存期間、削除依頼への対応、バックアップ、同意証拠の確認責任者は業務責任者と確認が必要です。

開発用の確認手順（Node.js 20以上・追加パッケージ不要）：

```text
npm run build
npm test
npm run preview
```

プレビューは`http://127.0.0.1:4173/`です。架空データをメモリだけに保存し、サーバーの終了で消えます。画像の文字読取とGoogle接続は行いません。

テストはCSVの引用符・改行、全列保持、ファイル重複、候補判定、同意と停止、競合、Google処理の代用品を使った保存・復旧・アクセス拒否・画像処理を確認します。実Googleサービスの動作保証とは分けて扱います。

同意日の日付はユーザー回答により、名刺交換日を優先し、空欄なら登録日を使用、両方空欄なら未記録と確定しました。今日の日付は補いません。

## 姓名とSansan全項目

姓・名、カナの姓・名を別々に入力します。参考CSVの全60列は、画面の基本欄と折りたたみ欄から編集できます。氏名・氏名カナの全体表記も別項目として保持し、空白から自動分割しません。詳細は[全60項目の対応表](docs/SANSAN_FIELD_COVERAGE.md)。

スプレッドシートの顧客一覧には、顧客IDの後にCSVと同じ順の60列と、同意・停止等を表示します。旧版の表は次の保存時に復旧記録を作って拡張します。セルの直接編集はアプリへ反映しません。原CSV・原行を残し、顧客の現在値と編集履歴は分けて保存します。

## 既存認証でコードを確認・反映する

`scripts/google-sync.mjs`は、保存済みのclasp認証を使ってGoogle公式Apps Script APIを呼びます。ブラウザのCookie、新しいログイン、追加パッケージは使いません。clasp本体のコマンド起動とは別の軽量な接続処理です。

手元だけに次の設定を置きます（どちらもGit管理対象外）。

- `.clasp.json`：対象の`scriptId`と`rootDir: "gas"`。実際のIDは指定されたGASから確認。
- `private-data/google-local-settings.json`：`expectedEmail`に許可された同期用アカウント、`accountName`に既存clasp認証の名前（通常`default`）。実値を公開しない。

```text
npm run google:check
npm run google:push
npm run google:deploy-private
```

最初はcheckだけ実行して差分をレビューします。pushは直前の確認時からGoogle側が変わっていないかを検査し、変更前のバックアップを保存して反映・読戻し照合します。Google側の「コード」等のファイル名を維持します。未知のファイルがある場合は反映を止めます。

deploy-privateは、Googleと手元のコードが一致し、マニフェストがMYSELF・USER_ACCESSINGの場合だけ版作成と本人限定の配置を行います。同じコードの再実行では既存の版・配置を照合します。前回の配置情報がローカルにあれば、そのID・説明・本人限定設定を照合して既存配置を更新し、URLを維持します。照合に失敗したら更新を止めます。認証情報、バックアップ、配置URLは`private-data/`に置き、公開リポジトリへ保存しません。

画面の起動処理は、独立した`src/boot.js`の後に、共通処理と画面処理を同じJavaScriptモジュールで読み込みます。Google配信画面で従来のscript配置が文法エラーになったための修正です。起動エラーや45秒を超える読込では再読込案内を表示します。ビルド後のHTML構造・構文と起動監視のテストも実行してください。

同期認証にSheets API権限がない、または同期ツール側のSheets APIが未有効でも、コード同期の失敗とは限りません。今回の確認ではGASの読取・反映・配置は成功しています。アプリ実行時のDrive/Sheets/Docs権限はユーザーが別途承認します。同期用の権限を広げたりAPIを有効化したりせず、用途を分けます。

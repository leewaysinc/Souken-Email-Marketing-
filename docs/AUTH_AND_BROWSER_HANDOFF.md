# 認証とブラウザの引き継ぎルール

記録日：2026-10-22。ユーザーから「普段のブラウザではログインが有効なのに、別プロジェクトでも再ログインを繰り返し求められる」と指摘を受けたための訂正と再発防止です。

## 今回確認できた事実

- ユーザーは普段見ている画面でログインが切れていないと説明した。
- AIが操作していた内蔵ブラウザではGoogle/Oktaの本人確認画面が出た。
- 現在の接続一覧に、ユーザーが普段使うChrome/Edgeはなかった。
- Google Driveの連携ツールではメタデータを取得できたが、GASコードの編集機能は提供されていない。
- これらは別々の接続経路。内蔵ブラウザの本人確認を根拠に、ユーザーの普段のブラウザもログアウトしているとは判断できない。
- AI側の画面をユーザーが操作できることを確認せず、そこでの再ログインを依頼した。案内が不十分だった。

現在の正しい課題名は「ユーザーのGoogleログイン切れ」ではなく、「作業に使う接続経路の確認・選択が必要」です。GASの初回権限承認はさらに別工程であり、完了の証拠はまだありません。

## 使い分けの提案

### GASのソース同期：clasp

Google公式のApps Script同期ツールclaspを使えば、ソースの取得・反映をWebエディタへの貼り付けに依存させず行えます。独立型GASにも対応します。

このPCには既存のclasp認証設定が存在します。ただし、適用されるアカウント、対象プロジェクトへの権限、認証の有効性、Apps Script APIの許可は未確認です。設定ファイルがあることを、接続成功と扱わないでください。認証情報そのものは公開資料やログに出しません。

次の担当者は、まず既存の接続で対象プロジェクトを読み取れるか確認します。再認証が必要と分かる前に新しいログインを依頼しません。新たな権限付与が必要なら、用途と範囲を説明し、ユーザーが操作できる通常のブラウザで承認できる手順にします。同期前には対象ID・アカウント・既存コードとの差分を確認します。

claspによるコード同期の認証は、アプリ自身がDrive・Sheets・Docsを使う初回承認とは別です。コード同期が成功しても、アプリの実行承認やデプロイが済んだとは扱いません。

参考：[Google公式claspガイド](https://developers.google.com/apps-script/guides/clasp)、[Apps Script APIの利用許可](https://developers.google.com/apps-script/api/how-tos/enable)。

### 画面操作：普段のブラウザの明示接続

画面確認・承認・デプロイ操作には、ユーザーとAIが同じブラウザの同じ対象タブを扱える構成が有用です。OpenAI公式には、ブラウザ拡張を設定し、チャットでChrome/Edge等を選択する方式が案内されています。

ただし、この環境の接続一覧に現在はそのブラウザがありません。拡張の利用可否や組織の許可を確認せず、利用できると断定しません。設定メニューやブラウザ候補が表示されない場合に、内蔵ブラウザへ戻って同じ再ログイン依頼を繰り返してはいけません。

参考：[公式ブラウザ拡張の設定手順](https://learn.chatgpt.com/docs/chrome-extension)。

## 今後ログインが必要に見えた場合の確認順

1. どの経路で失敗したかを記録する：内蔵ブラウザ／普段のChromeやEdge／Drive連携／clasp。
2. ユーザーの普段のログインと切り分ける。画面を確認していない場合は「ユーザー側の状態は未確認」とする。
3. 同じ経路の同じ画面をユーザーが操作できるかを確認する。
4. 既存の認証・連携で読み取り可能か確認する。認証情報やCookieをチャットへ貼ってもらわない。
5. 再認証や権限付与が本当に必要な場合だけ、対象、理由、必要な操作、完了の確認方法を伝える。
6. 接続成功を記録する。別の接続経路や別プロジェクトも成功したと推測しない。

この文書のclasp採用・ブラウザ接続は提案であり、導入・新規認証・API有効化・権限変更を実施した記録ではありません。

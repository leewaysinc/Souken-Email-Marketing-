# Sansan項目の対応と管理範囲

更新日：2026-10-22。参考CSVの列名・順番に一致する60列を対象とする。CSVの実顧客の値は掲載しない。

## 姓名と原本の扱い

姓・名、カナの姓・名を独立した文字列として保存・編集・照合する。空白から自動分割しない。元の「氏名」「氏名（カナ）」も独立して残す。一覧用の表示だけは姓と名を並べるが、この表示を保存キー・姓名の分割元にしない。双方に分離済み項目がある場合、重複候補は姓と名を個別に比較する。姓名未分離の旧データがある場合だけ全体表記による保守的な候補を出し、自動統合しない。

元CSVのバイト列とCSV原行の60値は変更しない。顧客の現在値60項目を別に持ち、編集前後は変更履歴に記録する。同じ人への取得履歴の関連付けでは、既存顧客の現在値を勝手に上書きしない。

旧版CSV登録はバッチID・レコード番号が一致する原行から欠けた項目を復元する。既に編集された項目は上書きしない。手入力の全体氏名に空白があっても姓・名へ推測分割しない。

## 画面とスプレッドシート

画面では姓名・会社・主要連絡先を先頭に表示し、残りを会社情報、氏名の元表記、住所・連絡先1、住所・連絡先2、Sansan管理情報の折りたたみ欄で編集する。下表の全60項目に重複のない入力欄がある。日付・識別子・フラグも原表記を残すため文字列として扱い、カナの空欄、先頭ゼロ、電話2・FAX・携帯・第2住所を別々に保持する。

スプレッドシートの顧客一覧は、顧客ID、元CSVと同じ順番の60列、取得経路・同意・停止・版番号等、管理用JSONの順で表示する。旧13列の表は見出しからJSON列を探して読み、次の保存時に復旧記録を先に残した上で拡張する。表示セルの直接編集はアプリへ反映しない。編集はアプリで行う。

不達フラグや重要度等の保存・編集対応は、それらを用いた自動配信・業務判断の実装を意味しない。メール送信機能は含まない。

## 検証範囲

自動テストで全60値の取込・編集・原行不変、旧13列表の移行、姓と名の境界が違う人の誤一致防止、カナ欠落、全60入力欄の一意性を検証する。実Google画面での確認結果は当日の進捗記録を参照する。参考CSVはローカルで構造・列対応を確認する用途に限り、今回の変更では実顧客をGoogleへ取り込まない。
